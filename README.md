# sure-document

**Documents for the sure stack** — agreements, notices, statements, coupons —
as **layout data**, rendered to HTML (and optionally PDF) with no reporting
engine, no Java, no designer, and no second source of truth.

The stack is agent-first. A document here is text a coding agent can read,
diff, generate and *verify*: a layout in TS/JSON plus a fixture that says what
the output must contain. That is the whole difference from the thing it
replaces — a 2007 JasperReports `.jasper` is a compiled Java serialisation that
only iReport can open, so nothing could check it and nothing could improve it.

```
layout (TS/JSON)  +  data (sure-state rows)  →  renderer  →  HTML  →  print / PDF
                                                   │
                                            guards + fixtures
```

## Why it exists

The first consumer's paper — an agreement, its notice page, a coupon sheet —
was generated by JasperReports from `.jrxml` designs. Those designs still exist
in that product's tree, and the stack has already ported them
coordinate-for-coordinate into a plain renderer. This package is that renderer,
generalised: the *fixed* mode keeps a legal form's boxes where the law and the
form put them; the *flow* mode carries documents whose length is data (a
statement with forty transactions, a cancellation notice).

## What it is not

| Not this | Because |
|---|---|
| a data layer (no SQL, no fetch, no joins) | data comes from **sure-state**; the server recomputes totals. A document that can query is an ORM with a ruler |
| a report designer | layouts are code/data, reviewable in a diff |
| a charting library | figures are SVG built from scales; no canvas, no animation, no dependency |
| a second catalog registry | component definitions live in **sure-store/components** (MIT), consumed through sure-factor |
| a human-first CLI | `--agent` is the mode with a complete machine contract; human output is the default view of the same data |

## Where it sits

| Package | Role in a document |
|---|---|
| `@shing.wong/sure-factor` | field metadata: labels, formats, limits — a document reuses them instead of inventing a second formatter; the catalog form (`tier`, `parameters`, `sure_ui`, `cssClasses`) is its shape, extended with `family`/`data`/`print`/`guards`/`fixture` |
| `@shing.wong/sure-ui` | the ink: theme tokens, the existing `table`/`markdown` blocks, and two new families — `document` (the sheet) and `figure` (charts) |
| `@shing.wong/sure-state` | the rows, and the events that say when they changed |
| `@shing.wong/sure-store` | the home of the component *definitions* (catalog YAML, MIT), with fixture goldens |
| **`@shing.wong/sure-document`** | the element model, expressions, formatters, pagination, renderers |

## Name

`sure-document`, not `sure-doc`: the family uses no abbreviations
(`sure-factor`, `sure-state`, `sure-web-testing`), and `doc` already means
"documentation" in every repository's `docs/`.

The same rule applies inside it, so there is exactly one spelling of the word
everywhere it can be typed:

| Surface | Name |
|---|---|
| package | `@shing.wong/sure-document` |
| sure-ui block | `document` (`sure-document__sheet`, …) |
| catalog entries | `document-table`, `document-totals`, `document-sheet`, … |
| CLI verb | `sure document render …` |
| TypeScript | `renderDocument`, `DocumentLayout` |

A few more bytes cost nothing; three spellings of one concept cost an agent a
wrong guess.
